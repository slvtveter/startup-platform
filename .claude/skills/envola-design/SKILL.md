# envola-design

Владелец Envola один пишет весь сайт. Ему тяжело самому ходить за референсами и каждый раз объяснять,
на что смотреть. Этот скилл делает это за него: **ищет паттерн в библиотеке → смотрит, как его решили
лучшие → предлагает 2–3 варианта → выбирает → внедряет → проверяет → выкатывает**.

`<skill>` ниже — `.claude/skills/envola-design`. Скрипты запускать из корня репозитория.
Playwright берётся из `apps/web/node_modules` (если нет — `cd apps/web && npm ci`).

## Сначала всегда

1. Прочитай `<skill>/references/brand.md` — продукт, токены, вкусы владельца, запреты. Это не обсуждается.
2. Определи режим по запросу:

| Запрос | Режим |
|---|---|
| «сделай / переделай / улучши X» | **Build** (полный цикл до прода) |
| «как это делают другие», «найди референсы», «исследуй X» | **Research** (без кода) |
| «проверь / аудит / что не так со страницей X» | **Audit** |
| «добавь сайт в референсы», «обнови библиотеку» | **Library** |

## Инструменты

```bash
node <skill>/scripts/refs.mjs "карточка лида"     # какой паттерн, у кого смотреть, есть ли разбор, свежи ли снимки
node <skill>/scripts/refs.mjs --tags               # все паттерны и покрытие
node <skill>/scripts/capture.mjs --tag lead-card   # снять референсы (кэш 30 дней; --force, --headed против 403)
node <skill>/scripts/capture.mjs --url http://localhost:3000/people --name local --page people   # снять свою страницу
node <skill>/scripts/sheet.mjs --tag person-card --page people --view card-1   # сводный лист для сравнения
node <skill>/scripts/audit.mjs http://localhost:3000/people   # машинный аудит против дизайн-системы и WCAG
```

Что даёт `capture.mjs` на каждую страницу (`<skill>/.cache/captures/<site>/<page>/`):
`d-first.jpg` первый экран 1440, `d-full.jpg` длинный скрин, `m-first.jpg` первый экран 390,
**`card-1.jpg`, `card-2.jpg` — автоматически найденные карточки списка** в полном размере,
`meta.json` с замерами (кегли, шрифты, радиусы, фоны, число CTA, и у карточек: паддинги, радиус, рамка,
кегли, строки текста по порядку), `text.txt` — текст страницы для разбора формулировок.

Смотри снимки через Read **листами** (`sheet.mjs`), а не по одному: так дешевле и сразу видно сравнение.
Длинные `d-full.jpg` при чтении ужимаются до нечитаемого — для деталей бери `card-*.jpg` и `d-first.jpg`.

Сайты за стеной антибота (в `sites.json` у них поле `access`) — смотри через Claude in Chrome, если он
подключён, или опирайся на готовый разбор паттерна.

## Build: от запроса до прода

**1. Понять задачу в коде.** Найди компонент и все места, где он используется (`grep`). Посмотри, какие данные
реально есть (схемы в `apps/api/app/schemas`, клиент `apps/web/src/lib/api`). Дизайн делается под реальные
поля; если варианту нужно новое поле API — это допустимо, но отметь в брифе.

**2. Достать знания.** `refs.mjs "<слова задачи>"` → тег. Прочитай `<skill>/library/patterns/<тег>.md`:
там уже разобраны референсы, консенсус, сильные ходы, антипаттерны и прошлые решения Envola.
Если разбора нет, ему больше 90 дней или задача про деталь, которой в разборе нет — сними референсы
(`capture.mjs --tag <тег>`), посмотри листы и **допиши разбор** по шаблону `references/pattern-template.md`.

**3. Снять «до».** `capture.mjs --url <страница локально или прод> --name envola-before` и `audit.mjs <url>`.

**4. Бриф с матрицей.** Коротко, в ответе пользователю или в `docs/research/<дата>-<тема>.md` при большой задаче:
- какую работу делает этот экран для человека (одна фраза: «основатель за 5 секунд решает, звать ли в чат»);
- матрица: 6–10 референсов (минимум 2 российских и 1 антипример) × что крупнее всего, какие поля по порядку,
  какие действия, приём, который стоит украсть;
- консенсус (что делают больше половины) — это база, от неё не отходим без причины;
- чем Envola отличается (студенты, без опыта, без HR-жаргона, бесплатно) и что поэтому не подходит.

**5. 2–3 варианта, а не один.** Варианты должны отличаться идеей, а не цветом кнопки. Обычно:
- **A. Привычный** — как в российском эталоне (hh / Хабр Карьера). Безопасно, понятно сразу.
- **B. Сильный** — лучший приём из мировой ниши или продуктовых эталонов (Attio, Linear, YC).
- **C. Гибрид** — база A плюс один-два хода из B.

Каждый вариант — реальный код на токенах проекта (а не абстрактный макет): компонент-вариант на временной
странице `apps/web/src/app/design-lab/<тема>/page.tsx` с синтетическими данными (3–4 разных случая: полная
карточка, пустые поля, длинные строки, без фото). Удобно: `?v=A` показывает один вариант. Сними
`capture.mjs --url ".../design-lab/<тема>?v=A" --name lab-<тема> --page A` (и B, C) и собери лист
`sheet.mjs --images .../A/d-full.jpg,... --labels "A,B,C" --crop 1500`.

`design-lab/` в `.gitignore` и в git не попадает. Tailwind v4 сам gitignored-файлы не сканирует, поэтому в
`globals.css` стоит `@source "./design-lab"`; **после создания новой lab-страницы перезапусти dev-сервер**
(с `rm -rf .next`), иначе произвольные классы вроде `size-[72px]` не сгенерируются и вариант будет выглядеть
сломанным. Синтетика должна проходить типы API (`npx tsc --noEmit`): уровни опыта только
`no_experience | courses | internship | junior`, у навыка есть `category`.

**6. Выбор.** Оцени варианты по рубрике `references/rubric.md` (баллы в таблице) и порекомендуй один.
- Если пользователь на связи и решение вкусовое (крупная смена вида, главная, бренд) — покажи лист и рекомендацию,
  спроси через AskUserQuestion с превью. Владелец любит выбирать из вариантов глазами.
- Если пользователь сказал «сам выбери / делай» или изменение небольшое и следует консенсусу — выбирай сам и
  в итоге объясни почему, с листом вариантов.

**7. Внедрение.** Ветка от свежего `main`, правка настоящего компонента, только токены и шкалы из `brand.md`,
переиспользование `components/ui` и `components/domain`. Перед правкой общих файлов проверь `ListAgents`:
параллельно могут работать другие сессии. Тексты — по правилам из `brand.md` (коротко, на «ты», без механики).

**8. Проверка (обязательно, не пропускать).**
- `audit.mjs` на изменённых страницах: 0 fail; warn по шкалам только осознанные.
- Снимок «после» и лист «до / после» на 1440 и 390 — посмотри глазами: обрезки, переносы, пустые поля, длинные имена.
- `make lint`, `cd apps/web && npx tsc --noEmit`, затронутые e2e (`npx playwright test <spec>`).
- Сверка с рубрикой: вариант после внедрения не потерял того, за что его выбрали.

**9. Выкатка.** PR: что меняли, какие референсы и приёмы взяли (со ссылками), лист «до / после», результат
аудита. Зелёный CI → merge (владелец разрешил) → после деплоя `audit.mjs https://envola.ru/<страница>` и снимок прода.

**10. Записать решение.** В `library/patterns/<тег>.md`, раздел «Решения Envola»: дата, PR, какой вариант
выбран и почему, что отвергнуто. Так библиотека умнеет с каждой задачей и решения не принимаются повторно.

## Стенд и вход для снимков

- Код из своей ветки или worktree: `cd apps/web && API_INTERNAL_URL=http://localhost:8080 npx next dev -p 3100`
  (зависимости — `npm ci`, симлинк `node_modules` Turbopack не принимает). Стек `make dev` на :8080 может
  обслуживать чужую ветку параллельной сессии — не перезапускай его.
- На :3100 картинки `/media` отдаёт только Caddy: добавляй `--media-from http://localhost:8080` к `capture.mjs`.
  POST-запросы с :3100 режет CSRF (Origin), поэтому кликать «Принять» там нельзя, а e2e гоняет CI.
- Залогиненные страницы (пароль сида `demo12345`, основатель с откликами — `alina@example.com`):
  ```bash
  T=$(curl -s -c - -X POST http://localhost:8080/api/auth/login -H 'content-type: application/json' \
      -d '{"email":"alina@example.com","password":"demo12345"}' | awk '/session/{print $NF}')
  node <skill>/scripts/capture.mjs --url http://localhost:3100/me/startups/vkusnoryadom --name after --page incoming \
      --cookie "session=$T" --media-from http://localhost:8080 --force
  node <skill>/scripts/audit.mjs http://localhost:3100/me/startups/vkusnoryadom --cookie "session=$T" --selector article
  ```
- «До» со своей ветки: `git stash -- <файл>`, снять, `git stash pop`, снять «после».
- Не запускай `prettier --write` без флагов: конфига нет, он переформатирует файл под ширину 80 и раздует дифф.
  Репозиторий пишется строками до ~150: `npx prettier --print-width 150`.
- Детектор карточек (`card-*.jpg`) иногда берёт целые секции. Сверяйся с `meta.json → cards[].lines`, а если там
  секция, смотри `d-first.jpg`.

## Research

Шаги 2 и 4 из Build. Результат — `docs/research/<дата>-<тема>.md` (матрица, консенсус, сильные ходы,
рекомендация для Envola с приоритетами P1/P2/P3) и обновлённый разбор паттерна. Кода не трогать.

## Audit

1. `audit.mjs <urls>` на 1440 и 390 — машинные проблемы.
2. Сними страницу и её главные референсы, собери лист рядом — глазами по рубрике `references/rubric.md`.
3. Отчёт: что сломано (fail), что расходится с системой, что хуже конкурентов — с конкретным референсом
   и правкой для каждого пункта, по приоритету. Если просили «и почини» — дальше по Build с шага 7.

## Library

- Новый сайт: добавь запись в `library/sites.json` (`id`, `name`, `region`, `kind`, `why` одной фразой —
  чем он полезен Envola, `tags` из словаря `tags`, `pages` с `key`: home / catalog / people / detail / profile).
  Сними `capture.mjs --site <id>`, проверь `meta.json` (`ok`, не заглушка антибота). Допиши его в нужные разборы.
- Новый паттерн: добавь тег с `desc` и `aliases` (русские слова, которыми его назовёт владелец) и разбор по шаблону.
- Раз в пару месяцев: `capture.mjs --all --force`, сравнить, что поменялось у ключевых конкурентов.

## Чего не делать

- Не копировать чужой интерфейс целиком и не тащить чужие картинки, шрифты и тексты в продукт.
- Не предлагать то, что владелец уже отверг (список в `brand.md`).
- Не останавливаться на одном варианте, если задача вкусовая, и не делать пять, если это мелкая правка.
- Не выкатывать без аудита и без снимка «после» на 390.
