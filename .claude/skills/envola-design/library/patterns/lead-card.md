# lead-card: карточка лида / кандидата / отклика

Обновлено: 2026-10-31. Смотрели: folk, attio, twenty, ashby, huntflow, teamtailor (продуктовые скрины на
главных) + hh (резюме в выдаче работодателя), Хабр Карьера (специалисты). Pipedrive за стеной антибота.
Снимки: `capture.mjs --tag lead-card`.

В Envola «лид» — это **отклик или приглашение глазами основателя** (`ApplicationCard`, `perspective="founder"`,
страница `/me/startups/[slug]`). Тот же паттерн нужен для «моих откликов» кандидата и, позже, для CRM-вида
«все кандидаты по всем ролям».

## Работа, которую делает этот элемент

Основатель за 5 секунд решает: **звать ли этого человека в чат**. Для этого ему нужно: кто это (лицо, имя,
роль, уровень), на какую роль откликнулся, что написал, и одна кнопка решения.

## Консенсус

1. **Лицо всегда.** Фото или аватар слева, 40–64 px в списке, 64–96 px в панели.
2. **Имя — главное**, сразу под или рядом: роль/должность и одна строка контекста (компания, грейд, город).
3. **Стадия/статус — цветной чип** в той же строке, а не отдельный блок. Цвет = смысл (ждёт / принят / отказ).
4. Детали не вываливаются в карточку: список компактный, подробности — по клику (панель, страница, раскрытие).
5. Действия по месту: основное одно (в CRM — «следующий шаг»), остальное в меню.
6. Время и активность («вчера», «12 взаимодействий») — мелким серым, но всегда видно.

## Сильные ходы

- **Сводка одной фразой** (folk «Relation summary»): что произошло и что дальше, вместо таймлайна в карточке.
- **Список + боковая панель** (folk, Attio): основатель листает отклики, не уходя со страницы.
- **Счётчики во вкладках** (folk): «Сообщения 4» сразу показывает, где жизнь.
- **Сигнал живости** (hh «был вчера», «Активно ищет работу»): кандидат, который был на сайте сегодня, ответит быстрее.
- **Шаблоны отказа** (у нас уже есть) — в ATS это стандарт, оставить.

## Антипаттерны

- Карточка без фото, только инициалы, когда фото у человека есть (так было у Envola до 2026-10-31: `PersonAvatar` игнорировал `avatar_url`).
- Статус-таймлайн из двух шагов «Отправлен → Ждёт решения» на каждой карточке: место есть, смысла нет.
- Сообщение кандидата в сером блоке на всю ширину над кнопками: решение уезжает вниз.
- HR-жаргон: «пайплайн», «скоринг», «квалифицирован» — наши основатели так не говорят.
- Три равноправные кнопки (Принять / Отклонить / Профиль / Написать) — непонятно, что главное.

## Для Envola

Берём: фото + имя + роль/уровень в шапке, статус чипом справа, сводку «на роль X · N дней назад», сообщение
кандидата коротко с «Показать целиком», одно главное действие. Список + панель — когда откликов станет много
(сейчас единицы, страница-список достаточна).
Не берём: канбан (стадий у нас две), таблицу, AI-сводку (зарубежные LLM нельзя по 152-ФЗ).

**Анатомия по умолчанию (основатель видит отклик):**
1. Шапка: фото 56 (или инициалы) · **имя** (ссылка на профиль) · строка «Роль в профиле · уровень · город» · справа чип статуса.
2. Контекст: «Откликнулся на **Frontend** · 2 дня назад» (или «Ты пригласил на …»).
3. Навыки: до 5 серых чипов, «+N».
4. Сообщение кандидата: 3 строки, «Показать целиком».
5. Действия: **Принять** (залитая) · Отклонить (outline) · справа «Написать» иконкой-текстом. После решения — только «Написать».
6. Контакты после принятия: строкой Telegram / Email на мягком зелёном.
